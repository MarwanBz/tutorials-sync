## Codebase Patterns

- When updating Convex schema with new fields, you must also update the validators in posts.ts (both syncPosts and syncPostsPublic mutations)
- The sync script uses comma-separated strings for concepts in frontmatter (e.g., "Git,Aliases,Zsh") which syncs as a string field, not array
- Convex validators use v.optional(v.union(v.null(), v.number())) for nullable number fields
- Always include lastSyncedAt timestamp when patching posts during sync

  - concepts: v.optional(v.string()) - Comma-separated concepts
  - source_repo: v.optional(v.string()) - Source repository name
  - understanding_score: v.optional(v.union(v.null(), v.number())) - Quiz score 1-10 or null
  - last_quizzed: v.optional(v.string()) - Date string when last quizzed
  - prerequisites: v.optional(v.array(v.string())) - Array of tutorial slugs
  - created: v.optional(v.string()) - Creation date

- Updated posts.ts validators in both syncPosts and syncPostsPublic mutations to accept tutorial fields
- Updated patch operations in both mutations to sync tutorial fields

**Decisions made and reasoning:**
- Used v.optional(v.union(v.null(), v.number())) for understanding_score because it needs to be either a number (1-10) or null - not undefined
- Stored concepts as string (comma-separated) rather than array to match the sync script's format which uses frontmatter like "concepts: Git,Aliases,Zsh"
- Added all tutorial-specific fields in both mutation validators (syncPosts and syncPostsPublic) to ensure consistency

**Learnings for future iterations:**
- Convex v.null() is the correct syntax (not v.null_())
